jig — agent guide
=================

What jig is
-----------
jig renders project templates. A template is a directory of files plus a
jig.json manifest declaring its variables; rendering walks the tree,
renders file/dir names and text contents with Go text/template, and copies
binaries verbatim.

The trust model: templates are inert data. No template-supplied program
ever runs at render time — rendering evaluates only the standard template
language and jig's registered, reviewed functions; a template cannot
execute a script, hook, or shell command. Rendered paths are contained to
the output directory, symlinks are rejected unless --trust is given, and
special files (FIFOs, devices, sockets) are rejected outright — this
includes verbatim directories. Rendering a template you did not write is
safe at render time.

Where templates come from
-------------------------
jig never fetches templates: clone a repo and point --templates-dir (or
JIG_TEMPLATES_DIR) at it. A public registry of ready-made templates lives
at https://github.com/cliwright/jig-templates:

    git clone https://github.com/cliwright/jig-templates ~/jig-templates
    jig render --template python/astral-pytest-zensical/tool \
        --templates-dir ~/jig-templates --output .

Running jig non-interactively
-----------------------------
You are almost certainly not on a TTY, and prompting requires one. Always
pass values explicitly:

    jig render --template <name> --output <dir> --var KEY=value [--var ...]
    jig render --template <name> --output <dir> --vars-file values.json

--vars-file always renders non-interactively. --var renders
non-interactively when stdin is not a terminal (yours is not); on a TTY,
--var only pre-sets values and prompting still runs, with interactive
answers winning. Anything not set takes its manifest default (defaults may
derive from variables you did set).

Typical workflow
----------------
    # authoring a template
    jig new python/std/lib --templates-dir ./templates
    # ... edit ./templates/python/std/lib/v1/{{.PROJECT_NAME}}/ ...
    jig check --template python/std/lib --templates-dir ./templates
    jig bump python/std/lib --templates-dir ./templates   # v1 -> v2

    # using a template
    jig render --template python/std/lib --templates-dir ./templates \
        --output ./out --var PROJECT_NAME=widget

Discovering more
----------------
This text is deliberately stable; flags and details are not documented
here on purpose. Run:

    jig --help
    jig <command> --help

The full documentation is embedded in this binary — always the right
docs for the version you are running:

    jig docs              list the available pages
    jig docs <page>       print one as markdown (e.g. jig docs manifest)

Full documentation (web): https://jig.cliwright.dev
  - CLI reference, the jig.json manifest (variables, derived defaults,
    choices, patterns), template syntax and string helpers, and the ADRs
    explaining why jig is designed this way (including rejected ideas).
    The ADRs are web-only; jig docs serves the operational pages.

Source code: https://github.com/cliwright/jig (a published mirror of the
development monorepo; issues and PRs welcome there).
